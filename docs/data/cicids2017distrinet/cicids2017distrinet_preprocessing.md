# CIC-IDS-2017 DistriNet: full EDA and preprocessing write-up

## 1. Purpose and experimental scope

This document records the exploratory data analysis (EDA), methodological decisions,
implementation, and verification of the preprocessing pipeline used for the B.Sc.
thesis experiments with two classifier targets: binary intrusion detection and
five-category classification.

The dataset is the corrected/relabelled **five-file DistriNet CIC-IDS-2017 release**
under `data/raw/CICIDS_2017_Distrinet/`. It is not the original eight-file CIC
`MachineLearningCSV` release. The two releases differ in file layout, schema, labels,
row counts, and CICFlowMeter behavior. Consequently, the five corrected files are
processed directly by:

- [`scripts/preprocess_cicids2017_distrinet.py`](../../../scripts/preprocess_cicids2017_distrinet.py)

They are **not** passed through `scripts/merge_cicids2017.py`, which explicitly
hard-codes the eight original TrafficLabelling files.

The final method is:

> **A leakage-controlled within-campaign split using chronological partitions within
> each retained source attack label, exact-duplicate removal, and training-only
> estimation of preprocessing statistics.**

The end-to-end pipeline is:

```text
five corrected DistriNet CSVs
→ validate inventory and schema
→ deterministic row-local cleaning with source provenance
→ map supported source labels to Benign/DoS/DDoS/Recon/BruteForce
→ discard unsupported categories before split construction
→ canonical float32 conversion
→ global exact duplicate removal on modelling features + category label
→ chronological 70/15/15 split independently inside each retained source label
→ encode binary and five-category targets
→ fit RobustScaler and class weights on training only
→ transform validation and test with the fitted scaler
→ save Parquet datasets, NumPy matrices, encoders, scaler, weights, and audit reports
→ assert source-label coverage, within-source chronology, and split disjointness
```

This is a **closed-set two-head classification dataset**: every retained source
attack label, and therefore every mapped category, appears in train, validation,
and test. It intentionally does not evaluate independent future attack-family or
attack-campaign generalization. CIC-IDS-2017 usually contains only one capture
window/tool invocation for a given source attack label; therefore partitions remain
chronological segments of the same campaigns. The split is leakage-controlled, not
completely leakage-free.

## 2. Research background and why the corrected release is used

### 2.1 Original CIC-IDS-2017

The University of New Brunswick CIC-IDS-2017 experiment captured five weekdays of
traffic from 3–7 July 2017. Monday contained benign traffic; attacks were scheduled
on Tuesday through Friday. The original release was distributed as eight labelled
CSV files generated by CICFlowMeter.

### 2.2 DistriNet findings

Engelen, Rimmer, and Joosen's 2021 CIC-IDS-2017 troubleshooting study identified
problems throughout the original creation pipeline, including:

- TCP flows being terminated after the first FIN rather than the complete FIN
  exchange;
- RST packets not correctly terminating flows;
- TCP appendix artifacts and sometimes reversed flow directions;
- broad time/IP-based labelling that marked empty or failed connections as attacks;
- shortcut learning from host-specific identifiers and timestamp;
- a misimplemented DoS Hulk scenario;
- aggregate metrics concealing severe rare-class and per-class failures.

Liu et al.'s 2022 error-prevalence study expanded this audit across attack
orchestration, feature generation, documentation, and labels. DistriNet released
corrected flow-generation tooling, explicit attack-specific labelling logic, and
recreated datasets.

The corrected release reduces known errors, but it does not make the experiment a
set of independent real-world attack campaigns. Tool, host, service, and timing
artifacts remain relevant when interpreting results.

### 2.3 Attempted flows

DistriNet introduced `- Attempted` labels for flows intended to participate in an
attack but not exhibiting a complete malicious effect, for example because no
payload was sent or the target was unavailable. Their download guidance states that
Attempted flows must not be treated as a separate ML class and recommends relabelling
them benign when uncertain.

The local CSVs contain Attempted suffixes but do not include the more detailed
`Attempted Category` field referenced by current DistriNet labelling code. The
default policy is therefore:

```text
<attack> - Attempted → source_label BENIGN → category Benign
```

The source value is preserved as `original_label`, and `is_attempted` is saved as
metadata. An explicit `--attempted-policy parent` option is available for a separate
intent-oriented experiment, but those results must not be mixed with the default
benign-policy baseline.

## 4. Actual local schema

### 4.1 Schema summary

All five headers match exactly: **84 columns**.

- Identifier/context fields: `Flow ID`, `Src IP`, `Dst IP`, `Timestamp`.
- Label: `Label`.
- Numeric modelling candidates: **79 columns**.

The five non-model fields are removed from the model/VAE feature matrix. The pipeline adds
further metadata—source filename/day/row, stable sample ID, parsed time, original/fine/binary
labels—but keeps all of it outside `X_*`.

### 4.2 Differences from the original eight-file release

The local corrected schema uses names such as `Src IP`, `Dst IP`,
`Total Fwd Packet`, and `FWD Init Win Bytes`. It contains one
`Fwd Header Length`; the duplicated header in the original CIC release is absent.
`RST Flag Count` is present, and flag counts are not restricted to binary values.

The local export does not contain:

- `Attempted Category`;
- `Total TCP Flow Time`;
- the additional ICMP fields referenced by the current DistriNet labelling notebook.

The local bytes and measured header are therefore treated as the source of truth;
missing fields are not reconstructed or invented.

- maximum `Flow ID` multiplicity: **1,184**;
- tens of thousands of `Flow ID` values recur across pairs of days.

`Flow ID` is a textual 5-tuple, not a unique record or globally unique connection
identifier. It is therefore never used as a join key, deduplication key, or model
input. The stable row identity is `source_file:source_row`.

### 5.5 Timestamp analysis

- timestamp column: `Timestamp`;
- strict format: `%d/%m/%Y %I:%M:%S %p`;
- strict parse failures: **0**;
- missing values: **0**;
- mixed-format fallback recoveries: **0**;
- unparseable values: **0**.

The strings have one-second precision. Although DistriNet documents UTC and
microsecond capability in its corrected tooling, this CSV export does not retain
microseconds. Timestamps are parsed as UTC and stored in ISO form and as integer
Unix seconds.

Raw file order is not global chronological order: the five files contain
**885,738 adjacent timestamp reversals** in total. A row-index split would therefore
not be a temporal split. The preprocessing pipeline sorts by parsed timestamp and
uses source-day order and source row as deterministic tie-breakers.

Absolute timestamp is excluded from `X_*`. It is retained only for splitting,
provenance, and temporal analysis because attack type is strongly confounded with
day/time and DistriNet identified timestamp-based shortcut learning as a risk.

### 5.7 Negative physical values

Exactly **2,922 additional rows** have at least one negative numeric feature after
non-finite rows are excluded.

- `Flow IAT Min` is negative in 2,922 rows.
- Among those, 31 rows also have negative `Flow Duration`, `Flow Packets/s`,
  `Flow IAT Mean`, and `Flow IAT Max`.

Observed examples include `Flow IAT Min` of −1, −4, or −12 microseconds. Counts,
lengths, rates, and timing quantities in this schema are physically non-negative.
These rows are removed; values are not silently clipped to zero.

### 5.8 Duplicate analysis

Two duplicate definitions were examined:

1. all 84 raw fields, including identifiers and timestamp: 3,143 repeated records;
2. the model-relevant definition used by the final pipeline: all 79 canonical
   float32 features plus mapped category label.

The second definition is stricter for model leakage because it ignores metadata and
uses the exact precision consumed by the model. After deterministic cleaning:

| Measure | Result |
|---|---:|
| Rows before model-key deduplication | 2,096,133 |
| Exact duplicates removed | 15,754 |
| Percentage duplicated | 0.751574% |
| Rows after duplicate removal | **2,080,379** |

Casting before deduplication matters: decimal CSV values that differ below float32
precision otherwise become identical only after the split. The earliest
chronological occurrence is retained.

and DDoS dominate attack rows, while Heartbleed, SQL Injection, XSS, Infiltration,
and Bot are rare. Accuracy and weighted F1 alone would therefore conceal important
failures. Evaluation must include per-attack counts, confusion matrices, macro
metrics, and uncertainty.

No balancing is performed in preprocessing. If used later, sampling or class
weights must be derived from training only. Validation and test retain their
natural post-cleaning distributions.

## 6. Deterministic cleaning and merge

### 6.1 Inventory and schema checks

The pipeline requires exactly the five expected filenames. It normalizes column
names, rejects mismatched headers, and excludes any `Unnamed:` index artifact from
model features. The source CSVs are read-only.

### 6.2 Provenance

Every retained row receives:

- `sample_id = source_file:source_row`;
- source file and weekday;
- deterministic day order;
- original one-based CSV row;
- raw flow identifiers/IPs;
- ISO timestamp and integer epoch seconds;
- original label, normalized source label, mapped category, and Attempted flag.

The five parts are vertically concatenated into one logical dataset. There is no
relational join and `Flow ID` is never used as a key.

### 6.3 Why no separate merged intermediate is saved

The implementation cleans each daily part and then calls `pd.concat` before global
sorting, duplicate removal, or split construction. The operations applied before
concatenation—column normalization, numeric coercion, timestamp parsing, provenance
attachment, and invalid-row removal—are deterministic and row-local. They do not
learn a statistic from one file or from the complete dataset. Therefore:

```text
clean each file independently → concatenate
```

produces the same retained rows as:

```text
concatenate raw files → apply the same row-local cleaning
```

All dataset-level operations occur only after concatenation. In particular, exact
duplicate removal is global across the five files, labels are split from the merged
dataset, and the scaler is fitted later on training rows only.

The merged intermediate is not written as an additional file because no downstream
stage consumes it, it would duplicate substantial storage, and retaining an
unsplit all-data artifact creates an avoidable opportunity to fit preprocessing on
validation or test rows accidentally. Reproducibility instead comes from the five
input SHA-256 hashes, source provenance on every row, and the production manifest.
The three pristine Parquet splits can be concatenated and sorted by
`timestamp_epoch_seconds`, `source_day_order`, and `source_row` to reconstruct the
cleaned, deduplicated merged dataset.

### 6.4 Row-local cleaning results

No fitted statistics are used during cleaning.

| Source | Raw rows | Kept after cleaning/category filter | Removed |
|---|---:|---:|---:|
| Monday | 371,749 | 371,172 | 577 |

## 7. Why the split is chronological within each source attack label

### 7.1 Rejected whole-day split

A strict Mon–Wed train, Thursday validation, Friday test design isolates days and
attack campaigns, but it puts different attack families into different partitions.
That measures open-set temporal generalization rather than closed-set classification
of attacks represented during training.

### 7.2 Rejected random split

A random stratified row split would distribute temporally adjacent flows from the
same attack invocation into every partition. It would satisfy source-label coverage
but ignore time and create a stronger within-campaign similarity risk.

### 7.3 Chosen protocol

For each retained source attack label independently:

1. select all rows with that source label;
2. retain timestamp-ascending order from the globally sorted merged data;
3. break equal timestamps with day order and source row;
4. allocate approximately 70% train, 15% validation, and 15% test;
5. use deterministic largest-remainder apportionment;
6. require at least one row per partition;
7. concatenate all source-label train, validation, and test blocks.

The source-label boundary matters for the five-category closed-set target. The
former category-only split placed all 7,562 `DoS GoldenEye` rows in test while
placing none in train or validation, so weak classifiers rejected an unseen attack
subtype as Benign. Source-label splitting preserves chronology without creating that
accidental open-set test. No random shuffle occurs before membership assignment.
Training may later be shuffled by a seeded data loader without changing membership.

### 8.2 Minority-class handling

BruteForce is the smallest retained category. Rows are not oversampled or duplicated.
The classifier runner uses train-only inverse-frequency weights by default:
`n_samples / (n_classes * class_count)`. The former effective-number setting with
`beta=0.999` saturated near `0.001` for every class and provided effectively no
imbalance correction.

```text
Category: Benign 0.252510, DoS 2.425229, DDoS 4.375270,
          Recon 2.616570, BruteForce 59.903950
Binary:   Benign 0.631275, Attack 2.404395
```

The runner applies these weights to both heads' cross-entropy losses and records
the exact counts, method, formula, and weights in
`outputs/cicids2017distrinet/class_weights.json`.

## 10. Train-only learned preprocessing

After split membership is immutable:

1. the 79-column pristine training matrix is materialized as float32;
2. `RobustScaler` is fitted on the **1,456,265 training rows only**;
3. validation and test are transformed using the fitted training center/IQR;
4. the scaler is persisted as `scaler.pkl`;
5. scaled and pristine matrices are both saved.

No imputation, feature selection, quantile clipping, PCA, balancing, or sampling is
performed in this stage.

The train split has three constant-zero fields:

- `Fwd URG Flags`;
- `Bwd URG Flags`;
- `URG Flag Count`.

They are reported but retained. Removing a field that is constant in train but not
in later partitions could erase future information and create new duplicate feature
vectors. `RobustScaler` safely handles train-constant features with unit scale.

Any later learned preprocessing must obey the same boundary:

- feature selection: train only;
- imputation values: train only;
- correlation/variance thresholds: train only;
- min/max or quantile bounds: train only;
- perturbability and constraint mining: train only;
- class weights and balancing: train only;
- VAE training: train only;
- classifier threshold, attack epsilon, PGD/CW and model hyperparameters: validation;
- final results: test once after all choices are frozen.

## 11. Leakage and overlap audit

### 11.1 Membership, source-label coverage, and chronology

The final run asserts:

- split indices are disjoint and exhaustive;
- canonical `sample_id` values do not cross splits;
- every retained source attack label and mapped category occurs in all three splits;
- for every source label, the latest train timestamp is not later than the earliest
  validation timestamp;
- for every source label, the earliest validation timestamp is not later than the
  earliest test timestamp;
- no exact feature-plus-category duplicate crosses partitions.

All assertions passed.

### 11.2 Pairwise overlap results

| Check | Train ↔ validation | Train ↔ test | Validation ↔ test |
|---|---:|---:|---:|
| Shared canonical sample IDs | 0 | 0 | 0 |
| Shared feature + category-label fingerprints | 0 | 0 | 0 |
| Shared feature-only fingerprints | 0 | 0 | 1 |

### 11.3 Remaining feature-only conflict

One canonical 79-feature float32 vector appears under two different labels:

- validation: `Thursday-WorkingHours.csv:230785`, timestamp
  `2017-07-06T20:27:47Z`, category `Benign`;
- test: `Friday-WorkingHours.csv:321856`, timestamp
  `2017-07-07T20:08:44Z`, category `Recon`.

The model vectors are exactly equal, but the category labels differ. The duplicate
key is features **plus category**, so these are not duplicate labelled samples and
neither is removed. This is a label ambiguity/feature collision rather than shared
row identity. It is recorded verbatim in `leakage_audit.json`. Neither validation
nor test has a feature-only overlap with train.

## 14. Methodological interpretation and limitations

### 14.1 What the split controls

- no random assignment before split construction;
- chronological order within every retained source attack label;
- deterministic tie-breaking;
- global removal of identical category-labelled model samples;
- disjoint source-record identities;
- complete source-label and mapped-category coverage;
- training-only learned preprocessing;
- validation-only hyperparameter selection;
- test isolation for final reporting.

### 14.2 What the split cannot control

For every retained source attack label, train, validation, and test remain
chronological segments of the same campaign, using the same attacker, victim, tool,
service, and configuration. The split cannot create independent attack repetitions
that CIC-IDS-2017 never captured. Tool-specific shortcuts and local network
artifacts can therefore remain.

Appropriate wording:

> **A leakage-controlled, source-label-stratified within-campaign chronological
> split for closed-set binary and five-category classification.**

Inappropriate claims:

- completely leakage-free;
- independent attack-campaign generalization;
- future-day or open-set attack-family generalization;
- reliable standalone conclusions for Heartbleed, SQL Injection, XSS, or
  Infiltration from one to five evaluation samples.

A whole-day split can be reported as a separate open-set experiment, but it answers
a different question and is not the primary adversarial-evasion split.

Classifier validation and test difficulty also differ materially. For example, the
SimpleMLP category checkpoint selected on validation reached 89.19% validation
macro F1 but 97.73% test macro F1. The test score is therefore not evidence of
stationary future-campaign performance.

### 14.3 DoS Hulk caveat

DistriNet documents that the DoS Hulk implementation in CIC-IDS-2017 used
`Connection: close`, undermining the intended Keep-Alive attack mechanism. Hulk
traffic remains anomalous, but results should not be generalized to correctly
implemented DoS Hulk campaigns without qualification.
